# v0.1.1 — Measurement Fix（已实施）

版本：`0.1.1-measurement`（commit 见 git log）
状态：**P0 全部完成并实弹验证**

## Review 结论：v0.1.0 的两个 P0 口径错误

v0.1.0 把"leader 赚多少"和"follower 能赚多少"混在一个 `markouts` 表里，
基点全是 `TradeTime`，而 replicability / chase 分析直接消费它：

| 问题 | 错误表现 | 根因文件 |
|---|---|---|
| P0-1 Replicability 算错对象 | 测的是"钱包买完涨不涨"，不是"我收到后再买赚不赚" | `internal/analyze/actors.go` 直接消费 leader markouts |
| P0-2 chase 同义反复 | 用 `ReturnPct` 自己分桶又统计自己 → 20%+ 桶 avg +90% 的假象 | `internal/analyze/research.go` `Chase()` |

GMGN REST 中位源延迟 ~140s 的实测使这个问题更严重：leader 买完 +30%，
我们收到时可能已回落 —— 旧口径会把不可复制的 actor 标成 highly
replicable。

## 修复设计：三变量模型

```text
LeaderPrice (price_usd @ TradeTime)
     │
     ▼
EntryPrice (kline close @ ReceivedAt 时刻)   ← 新：follower 入场价
     │  Chase = EntryPrice/LeaderPrice − 1     ← 新：追价定义
     ▼
ExitPrice (kline close @ ReceivedAt + H)
     │  FollowerReturn(H) = ExitPrice/EntryPrice − 1
```

## 精确改动清单

### Schema — `internal/storage/migrations/003_measurement.sql`（已实施）

`markouts` 表重建：

```sql
-- 旧: UNIQUE(event_id, horizon_ms), 基点隐含 = trade_time
-- 新:
kind      TEXT NOT NULL DEFAULT 'leader'   -- 'leader' | 'follower'
base_ms   INTEGER NOT NULL                 -- leader: trade_time; follower: received_at
base_price REAL                            -- leader: price_usd（立即可填）;
                                           -- follower: ReceivedAt 价格（采样时填, NULL 前不可用）
UNIQUE(event_id, kind, horizon_ms)
```

老行迁移为 `leader`，`base_ms` 从 `trade_events.trade_time` 回填。
**规则：分析代码必须按 kind 过滤，两口径永不混用。**

### storage — `internal/storage/markouts.go`（已实施）

- `CreateMarkouts(e, kind, basePrice *float64, horizons, createdAt)` — follower 传 `nil`
- `SetEntryPrice(eventID, kind, horizon, price)` — follower 行填 ReceivedAt 入场价
- `DueMarkouts` — 排序改为 **follower 优先 + 最新优先**，防止 dead token 的
  老 leader 行饿死新数据（实测饿死 bug，见下）
- `MarkoutsAt(kind, horizon)` — join 事件，返回新增字段：
  `ChasePct = (base_price / price_usd − 1) × 100`

### markout engine — `internal/markout/engine.go`（已实施）

follower 行**双阶段采样**（同一 kline 响应内完成）：

1. `base_price IS NULL` → `lastCloseAtOrBefore(base_ms)`（ReceivedAt 时刻
   正在进行的蜡烛收盘价 = 你实际能成交的价）→ `SetEntryPrice`
2. `base_price` 就绪且 due → `firstCloseAtOrAfter(base_ms + horizon)` → `FillMarkout`

另修复：kline 空响应的 token 进 `skipUntil`（15 分钟退避）——dead token
不再每 tick 烧预算。

### analyze — `internal/analyze/`（已实施）

| 文件 | 改动 |
|---|---|
| `research.go` `Chase()` | 桶 = `Bucket(ChasePct)`（追价），统计 = `ReturnPct`（follower 收益）→ 同义反复消除 |
| `actors.go` `Rank()` | replicability 改用 `MarkoutsAt("follower", h)` 的买单收益 |
| `actors.go` `Inspect()` | alpha decay 表 = follower 口径；新增 CHASE-CONDITIONED EV（`chase ≤ 5%` vs `chase > 10%` @5m） |

## P0-4 结论：RealizedPnL 口径限制（已文档化）

`RealizedPnL = Σ(sell.amount_usd − sell.buy_cost_usd)`（`buy_cost_usd > 0`
才计入）在 GMGN 数据形态下自洽：部分卖出按 GMGN 摊薄成本逐腿结算，总和与
全卖一致；缺失成本基数的卖单被跳过而非误计。

**未验证项（v0.2 工作）**：GMGN 的摊薄成本归属是否等于链上真实 realized
PnL，需要链上交易重构（E3 证据）才能验证。当前 Quality 的 PnL 一律视为
**GMGN-derived**，不可当最终真值。

## 实弹验证（2026-08-10，~30 分钟数据）

```text
CHASE @ 30s — follower EV vs entry chase (entry = price at ReceivedAt)
chase           N       WR        avg     median
<0%            95    41.1%     -5.26%     -2.09%
0-2%            3    66.7%    +18.22%     +3.31%
2-5%            6    50.0%    +16.66%     +5.44%
5-10%           5    40.0%     +0.86%     -0.03%
10-20%          5    40.0%    -13.22%     -3.39%
20%+            8    37.5%     -2.28%    -18.35%
```

旧口径 20%+ 桶 avg +90%（噪声）→ 新口径 **−2.3%**，10-20% 桶 −13%：
EV cliff 的形态开始出现。样本量不足，继续积累。
