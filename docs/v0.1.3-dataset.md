# v0.1.3 — Dataset & Observability（已实施）

版本：`0.1.3-dataset`

进入"数据开始有意义积累"阶段。开发线只做**不会因未来统计结果而推翻的
基础设施**；不做机制挖掘/评分/参数搜索（数据 snooping 防线）。

## 1. markout status：survival 从"一个比例"升级为 Data Quality

`markouts.status`（migration 006）把 `observed_price NULL` 拆成明确原因：

| status | 含义 |
|---|---|
| `pending` | 未到期 |
| `filled` | horizon 价格已采样 |
| `no_candle` | 蜡烛流在 horizon 前结束（token 停止交易）|
| `token_inactive` | token 无任何 kline |
| `api_error` | kline 请求失败（非 429）|
| `rate_limited` | 429，冷却闸关闭 |
| `lookback_miss` | entry 所需蜡烛超出拉取窗口 |
| `price_parse_error` | kline close 无法解析 |

首次采样尝试定终身（`status='pending'` 才可写），保证每行只有一个状态。
`no_candle` 与"蜡烛尚未可见"区分：流在 due−2×res 前结束 → 终局；否则
pending 重试。

新命令：

```bash
followedge analyze coverage
```

```text
MARKOUT COVERAGE @30s (follower)
  status           count
  filled            197    30.9%
  no_candle          ...    ...
  token_inactive     ...    ...
  coverage          197    30.9%  (filled / due)
```

**为什么重要**：`E[R | price available]` 有严重 selection bias —— 最差
的币全部掉出 EV 统计。首日 `survival@30s=31%` 意味着 EV 表只覆盖了
survivors；coverage 表让 bias 可见、可解释。

## 2. Coverage-aware EV（latency-ev 改造）

`analyze latency-ev` 改为 **census 驱动**：每个 due 行（filled 或否）都
入桶，输出：

```text
SOURCE AGE × FOLLOWER EV @ 5m — smart_money
age        due   fill    cover       WR    obs EV   median    cons EV
0-30s      180    122    67.8%    55.7%    +8.2%    +3.1%     +2.1%
120-180s   510     89    17.5%    40.0%   +20.0%    -2.0%    -27.2%
```

- `cover` = filled/due —— 若 age 越大 coverage 越低，EV 越高，那是
  survivorship，不是 alpha。
- `cons EV` = (Σ filled returns + (due−filled) × −noexit_loss) / due。
  默认 `--noexit-loss 100`（未定价样本按 -100% 计，最极端假设），可调。

## 3. Position episodes（migration 006）

`position_episodes` 表 + 全量重建（`RebuildEpisodes`，确定性、幂等）：
per (wallet, token) 按 trade_time 顺序把 BUY/BUY/SELL/SELL 重建成完整
episode：

```text
opened_at / closed_at / adds / reduces / capital_in / capital_out /
realized_pnl / hold_duration_s / status(open|closed|partial)
```

- sell 超出可见持仓 → `partial`（采集窗口前的数据缺口，明确标注不猜测）
- 命令：`followedge analyze episodes [--since 24h]`

未来研究单元从"单笔 trade"升级为"完整 episode"（持有时间、加仓习惯、
部分止盈、最终收益）。

## 4. Mechanism 数据契约（只定义，不评分）

`internal/mechanism/feature.go`：

```go
type Feature[T any] struct {
    Value      T
    ObservedAt time.Time // 数据真实可知时刻（非拉取时刻）
    Source     string
    Quality    string    // fresh | stale | estimated | missing
}

type EntryFeatures struct {
    TokenAge       *Feature[time.Duration]
    LiquidityUSD   *Feature[float64]
    SmartBuysBefore *Feature[int]
    ...
}
```

**没有** `if TokenAge < 20s { score += 30 }`。任何未来评分必须从这些
provenance 字段开始，且强制 `feature.observed_at ≤ decision_time`。

## 5. 统一时间模型（PIT 第一等公民）

| 概念 | 含义 | 约束 |
|---|---|---|
| `event_time` | 链上成交时间 | — |
| `source_received_at` | 我们收到 | ≥ event_time |
| `decision_time` | 策略做决定时刻 | ≥ source_received_at |
| `feature_observed_at` | 特征值真实可知时刻 | ≤ decision_time（否则 reject）|
| `entry_price_time` | entry 价真实代表时刻 | = candle open + res（已收盘蜡烛）|
| `outcome_time` | 结果价时刻 | ≥ entry_price_time + horizon |

Experiment Engine（v0.3）将强制 `feature_observed_at ≤ decision_time`。

## mechanism-ready gate（到 v0.2 的准入，量级参考）

```text
Raw events                     >= 5,000
Follower entry coverage        >= 60%  或已解释 coverage loss
Usable follower markouts       >= 1,000
Actors with >= 20 trades       >= 50
Actors with >= 20 follower obs >= 20
```

## v0.2 第一件事也不是"自动找策略"

1. Actor archetype 分类（early sniper / momentum / smart-money follower /
   launchpad specialist / swing / scaler / copy-flow exploiter / unknown），
   研究 Quality 与 FollowerEV 是否集中在某些 archetype —— **最赚钱的人
   未必适合跟**。
2. Cross-actor mechanism mining：只对真正 copyable 的 top-20 问共同点，
   不对全市场问。

## 明确不做（现在）
