## P0.5：follower entry 的 look-ahead 修复

### 问题

v0.1.1 的 entry 采样取 `lastCloseAtOrBefore(received_at)` —— received_at
所在 30s 蜡烛的**最终收盘价**。但该蜡烛在 received_at 之后最多 30s 才
收盘，其 close 包含未来信息：

```text
12:00:10  ReceivedAt
12:00:30  该 30s 蜡烛收盘（close 含 12:00:10→12:00:30 的价格）
12:00:40  markout worker 查 kline → 把 12:00:30 的价当 12:00:10 的 entry
```

= follower EV 被最多 +30s 的 look-ahead 污染。

### 修复（方案 D：上一根已收盘蜡烛，明确 stale）

关键洞察：**entry 是确定的历史值** —— "received_at 时刻最后已收盘的蜡烛
close"，数值与采样时机无关。所以：

```text
entry = lastCloseAtOrBefore(base_ms − res)   // res = 30s 分辨率
entry_observed_at = candle_open + res         // 价格真实代表时刻
```

进行中蜡烛被排除 → 无 look-ahead，stale 0..30s（诚实标注，宁可低估 edge）。

文件：
- `internal/storage/migrations/004_entry_point_in_time.sql` — 加
  `entry_observed_at` 列
- `internal/markout/engine.go` — entry 采样改已收盘蜡烛 + `entryCache`
  （同事件 6 行共享一次采样）；`lastCloseAtOrBefore` 返回蜡烛开盘时刻
- `internal/storage/markouts.go` — `SetEntryPrice(+observedAt)`、
  `MarkoutsAt` 返回 `EntryObservedAt`
- `internal/markout/engine_test.go` `TestSampleDueFollower` — 重写为
  陷阱测试：进行中蜡烛（close=1.10）若被使用，chase 会 +10% → 测试失败

## P1-5：retention 轻量版

`analyze chase` 尾部输出：

```text
survival@30s: 31% (197/638 due rows had a price — token alive at horizon)
```

`observed_price IS NULL` = token 在 horizon 前停止交易。这是
price_available 层次的代理（liquidity/tradeable 留待 enrichment）。

**首日实测发现（值得警惕）**：Solana meme 约 2/3 的 smart-money 事件
30s 后已无价格 —— 平均 EV 若为正，必须先回答"退出通道是否存在"。
这正是用户指出"+200% 平均被几个 winner 拉起来"风险的量化起点。
